## 요약

사내 서비스마다 언어와 배포 방식이 달랐고, 사람이 직접 배포하다 생긴 서비스 중단과 오류가 1년에 10회 이상 있었습니다. 개발 스택과 코드 규칙을 먼저 맞추고, GitHub Actions에서 테스트와 이미지 빌드, 배포까지 이어지도록 배포를 하나로 정리했습니다.

## 출발점

- 서비스마다 언어와 배포 방식이 달라 업데이트와 관리가 어려웠고, 새 서비스를 추가하기도 쉽지 않았습니다.
- 배포를 사람이 직접 하다 보니 오래 걸렸고, 배포 실수로 서비스 중단과 오류가 생겼습니다.
- 문제가 생겨도 알아채고 원인을 찾는 데 몇 시간씩 걸렸습니다.

## 정한 것

| 영역 | 정한 것 | 이유 |
|---|---|---|
| 개발 스택 | Python, Django, PHP, Spring, React | 빌드·배포 방식을 몇 가지로 줄이기 위해 |
| 코드 규칙 | PEP8, Airbnb JavaScript Style Guide | 서비스마다 다른 코드 형식을 하나로 맞추기 위해 |
| 이미지 | 환경별 Dockerfile, Alpine Linux, 빌드 캐시 | 이미지 크기와 빌드 시간을 줄이기 위해 |
| CI/CD | GitHub Actions | 변경 감지, 테스트, 이미지 빌드, 배포를 한 흐름으로 |
| 알림 | GitHub Actions, Prometheus, Grafana 이벤트를 메신저 배포 채널로 | 문제를 바로 알아채기 위해 |

## 결과

- push하면 빌드와 테스트를 거쳐 자동으로 배포되도록 바꿨습니다.
- 배포 절차가 하나로 정리되면서 배포 실수로 인한 장애가 줄었습니다.
- 알림이 배포 채널로 바로 오면서 문제를 알아채고 원인을 찾는 시간이 몇 시간에서 몇십 분으로 줄었습니다.
