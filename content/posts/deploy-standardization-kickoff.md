## 요약

2023년 1월, 사내 서비스 배포를 하나로 정리하는 프로젝트를 PM으로 시작했습니다. 바로 파이프라인을 만들지 않고, 개발 스택, 코드 규칙, 컨테이너 이미지 기준부터 정했습니다. 서비스마다 언어와 배포 방식이 다른 상태에서 자동화를 하면 파이프라인도 서비스 수만큼 생기기 때문입니다.

## 당시 상황

- 서비스마다 언어와 배포 방식이 달라 업데이트와 관리가 어려웠고, 새 서비스를 추가하기도 쉽지 않았습니다.
- 배포를 사람이 직접 해서 시간이 오래 걸렸습니다.
- 배포 실수로 인한 서비스 중단과 오류가 1년에 10회 이상 있었습니다.

## 정한 기준

| 항목 | 기준 |
|---|---|
| 개발 스택 | Python, Django, PHP, Spring, React |
| 코드 규칙 | PEP8, Airbnb JavaScript Style Guide |
| 컨테이너 | 환경별 Dockerfile |
| 이미지 | Alpine Linux 기반, 빌드 캐시 사용 |

## 프로젝트 목표

- 언어와 기술 스택을 표준화해 유지보수와 관리 부담을 줄이기
- 컨테이너 기반 환경으로 배포 환경을 안정적으로 만들기
- CI/CD 자동화와 표준화로 배포 과정을 안정화하기
- 서비스가 늘어나도 같은 방식으로 추가할 수 있는 구조 만들기

이 기준 위에 GitHub Actions, ArgoCD, kubeadm 3노드 Kubernetes를 올렸고, 결과는 2024년 1월에 [따로 정리](/posts/gitops-deploy-pipeline/)했습니다.
