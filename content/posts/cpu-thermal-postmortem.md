## 요약

특정 제조사의 1U 서버 모델에서 보드 내부 센서에 문제가 있어, 서버 안이 뜨거운데도 팬 속도가 올라가지 않았습니다. 그 결과 CPU 온도가 오르며 성능이 떨어졌습니다. 임시 방편으로 팬 속도의 최소값을 올리기로 했고, 대상은 4개 센터 1만 5천여 대였습니다. 관리 proxy를 거쳐 OOB 설정만 바꾸는 온라인 작업이라 서비스는 멈추지 않았고, 2021.06.02~03 이틀에 나눠 진행했습니다.

## 영향

- 대상: 특정 제조사의 1U 서버 모델, 4개 센터 1만 5천여 대
- 증상: 서버 내부 온도가 올라도 팬이 정상 속도로 돌지 않음, CPU 온도 상승, 성능 저하

## 왜 팬 최소 속도였나

- 근본 원인은 센서였지만, 1만 5천여 대의 하드웨어를 바로 바꿀 수는 없었습니다. 그래서 센서 값과 상관없이 팬이 일정 속도 이상 돌게 하는 임시 방편을 골랐습니다.
- 팬이 이미 정상적으로 도는 서버는 최소값보다 빠르게 돌고 있어서 영향이 없고, 팬이 최소 기준보다 느리던 서버만 속도가 올라갑니다. 문제 있는 서버만 골라낼 필요가 없었습니다.
- 서버를 끄지 않는 OOB 설정 변경이라 서비스 중단 없이 대량으로 적용할 수 있었습니다.
- 대신 작업 대수가 많고 장애가 나면 여파가 크기 때문에, 서버실 단위로 나누고 IDC 쪽 모니터링을 미리 준비했습니다.

## 남긴 점

- 온도 문제라고 해서 냉각 설비 부족이라고 단정하지 않습니다. 팬을 제어하는 센서 값과 BMC 설정도 함께 확인합니다.
- 대량 변경은 사전 테스트로 부작용(전력)을 먼저 확인하고, 작업 단위를 나누고, 현장 모니터링을 붙여야 했습니다.
- 임시 방편은 임시 방편으로 기록해 둡니다. 근본 원인(센서)이 남아 있다는 것을 잊지 않기 위해서입니다.

## GPU 노드에 적용하면

아래는 일반적인 내용입니다.

GPU는 온도가 올라가면 clock을 스스로 낮춥니다(thermal throttling). 장애로 잡히지 않고 학습 속도 저하로만 나타나서 놓치기 쉽습니다. 이번 사례처럼 센서 값이 틀리면 팬이 제때 올라가지 않는 것도 같습니다.

| 확인할 것 | 방법 |
|---|---|
| 현재 온도와 clock | `nvidia-smi -q -d TEMPERATURE,CLOCK` |
| clock이 낮아진 이유 | `nvidia-smi -q -d PERFORMANCE`의 Clocks Throttle Reasons(최근 드라이버는 Clocks Event Reasons)에서 Thermal Slowdown 항목 |
| 노드 간 비교 | DCGM으로 GPU 온도와 throttle 사유를 계속 수집해 같은 랙·모델끼리 비교 |
| 펌웨어 | BMC와 GPU 관련 firmware 버전을 노드별로 수집해 같은 조합끼리 묶어 보기 |
