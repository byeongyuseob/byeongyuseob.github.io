> 2020.04 – 2020.07 · Contributor · 관련 프로젝트: [서버 하드웨어 성능 저하 트러블슈팅](/work/hardware-troubleshooting/)

## 요약

특정 제조사 서버 모델에서 CPU P-state 기능과 메모리 성능이 서로 얽혀 성능이 떨어지는 문제가 있었다.
부품 교체, 메모리 구성 실험, UEFI 설정 조정을 차례로 거친 뒤
제조사 글로벌 기술지원팀과 함께 원인을 좁혔고, **UEFI v2.31 firmware** 로 해결했다.

## 영향

- 대상: 특정 제조사의 특정 서버 모델
- 증상: 메모리 성능 저하 → 서버 성능·신뢰도 하락, 운영 위험 증가

## 원인을 좁힌 순서

1. **하드웨어 호환성 배제** — CPU · 메모리 · 시스템 보드를 최신 부품으로 바꾼 뒤 Intel MLC(Memory Latency Checker)로 성능을 다시 쟀다.
2. **메모리 구성 실험** — 메모리 구성을 최소로 줄여 가며 CPU 와 메모리 사이의 상호작용을 확인했다.
3. **UEFI 설정 조정** — UEFI 설정을 초기화하고 IDC 환경에 맞게 하나씩 다시 맞췄다.
4. **firmware · 로그** — UEFI 와 BMC(IMM) firmware 를 최신으로 올리고, 영향받은 서버 로그를 분석해 원인과 다른 서버로의 영향 범위를 확인했다.
5. **제조사 협업** — 제조사 글로벌 기술지원팀과 자료를 주고받으며 해결을 앞당겼다.
6. **해결** — UEFI v2.31 firmware 로 P-state 관련 메모리 성능 문제가 풀렸다.

## 재발 방지

- 아직 증상이 없는 서버 그룹에도 BMC firmware 를 미리 적용
- 같은 모델에 UEFI · BMC firmware 를 함께 맞춘다

## 배운 것

- **전력 관리 설정이 성능 문제로 나타날 수 있다.** 증상은 메모리였지만 열쇠는 CPU 전력 상태와 firmware 였다.
- **부품을 바꿔도 같으면 소프트웨어 층을 본다.** 교체 → 구성 실험 → 설정 → firmware 순으로 층을 하나씩 걷어냈다.
- 혼자 확정하기 어려운 문제는 **제조사 firmware 이력과 기술지원**이 가장 빠른 길이다.
- 교체나 업데이트 뒤에는 **같은 도구(MLC)로 다시 재서** 확인한다.

## GPU 클러스터에서는 어떻게 보이나

일반적인 내용으로, 이 사례를 GPU 클러스터에 옮기면 이렇다.

- GPU 도 전력 상태(P-state)와 clock 정책이 성능에 직접 영향을 준다. 노드마다 persistence mode, 전력 제한, clock 설정이 다르면 같은 작업이 노드마다 다른 속도로 돈다.
- **driver · VBIOS · NVSwitch/NIC firmware 버전이 노드마다 섞이면** 원인 불명 성능 차이의 단골 원인이 된다. 버전을 노드 단위로 수집하고 어긋난 노드를 찾는다.
- 부품을 바꾸거나 firmware 를 올린 뒤에는 MLC 대신 `dcgmi diag` 와 `nccl-tests` 로 기준 성능을 다시 잰다. **고친 뒤 확인**까지가 한 묶음이다.
