세 프로젝트 모두 PM으로 진행했습니다.

## 2017: 서버 정보 수집 자동화

- 서버 작업을 기록하고 추적하는 티켓 시스템을 만들고 CMDB와 연동
- dmidecode, MegaRAID 등 제조사와 모델마다 다른 수집 도구를 하나의 명령으로 통합
- Ansible Playbook으로 서버 정보를 자동 수집해 중앙 DB에 저장하고 보고서로 출력
- 대당 수 분씩 걸리던 수작업 검수를 자동화했고, 입고·설치·변경 작업에서 모든 서버를 검수하게 됨

## 2019: 장애 대응 표준 절차 수립

- 과거 장애 기록과 로그를 분석해 반복되는 유형 정리
- 보안·컴플라이언스 기준에 맞는 대응 절차와 허용 명령어 목록 작성
- 장애 유형별 매뉴얼을 만들고 교육 진행
- 누가 맡아도 같은 절차로 대응하면서 처리 시간과 잘못된 명령으로 생기던 추가 장애가 줄었음

## 2021–22: 장애 관리 웹 개발

배경: 서버 6만여 대에서 하드웨어·OS 장애가 하루 30~40건 발생했고, 여러 사람이 서버에 직접 접속해 처리하다 보니 보안 위험과 처리 지연이 있었습니다.

- SSO와 proxy로 서버 접근 경로를 하나로 정리
- Ansible Dynamic Inventory로 서버 정보 관리
- 하드웨어·OS 장애를 유형별로 나누고 유형마다 Ansible Playbook 작성
- Flask와 Vue.js로 웹 콘솔 개발, Elasticsearch와 Kibana로 장애 추세 시각화
- 서버 직접 접속이 거의 없어졌고, 정형화된 장애는 Playbook 실행 한 번으로 수십 초 안에 처리
