## 요약

서버 6만 대+, 하드웨어·OS 장애가 하루 30~40건 나는 환경에서 운영 자동화 프로젝트 3건을 PM으로 진행했습니다. 2017년에 서버 정보 수집과 검수를 자동화했고, 2019년에 장애 대응 절차를 표준화했으며, 2021–22년에 그 절차를 Ansible Playbook과 웹 콘솔로 옮겼습니다. 앞 프로젝트에서 만든 것이 다음 프로젝트의 기반이 되도록 순서를 잡았습니다.

| 작업 대상은 Dynamic Inventory로 | 고정 inventory 파일 | 서버가 계속 입고되고 바뀌는 환경이라, CMDB를 원본으로 실시간으로 읽어야 대상이 틀리지 않습니다. |
| 처리 데이터를 Elasticsearch에 축적 | 처리 결과만 남김 | 유형별 장애 추세를 봐야 늘어나는 유형을 먼저 손볼 수 있습니다. |

## 정리

- 자동화는 한 번에 되지 않았습니다. 데이터(2017)가 있어야 대상을 자동으로 고를 수 있었고, 표준 절차(2019)가 있어야 Playbook으로 옮길 수 있었고, Playbook이 있어야 웹 콘솔로 열 수 있었습니다.
- 자동화의 효과는 속도만이 아니었습니다. 서버 직접 접속이 줄어 보안 위험이 줄었고, 경험과 상관없이 같은 결과가 나왔습니다.
