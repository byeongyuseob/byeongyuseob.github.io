## 알림 발신 게이트웨이 (2025.11 – 현재)

서비스마다 메신저 Bot 키와 메일 설정을 따로 갖고 있어서 키 관리가 흩어져 있었고, 어떤 서비스가 무엇을 보냈는지 확인하기 어려웠습니다.

{{< flow >}}
title: "알림 게이트웨이 흐름 · 단계를 눌러 보세요"
steps:
  - title: "사내 서비스"
    detail: "각 서비스는 등록할 때 한 번만 보여 주는 서비스 토큰 하나로 호출합니다."
  - title: "발신 API"
    sub: "토큰 · 중복 방지"
    detail: "Idempotency-Key 헤더로 같은 요청을 다시 보내도 한 번만 접수합니다. 메시지는 최대 2,000자입니다."
  - title: "접수 큐"
    detail: "접수된 요청은 현황 화면에서 접수, 재시도, 완료, 실패 상태로 볼 수 있습니다."
  - title: "Worker"
    sub: "at-least-once"
    detail: "단일 Worker가 at-least-once로 전달하고, 실패하면 1분, 5분, 15분 뒤 다시 시도합니다."
  - title: "메신저 · 메일"
    tone: "ok"
    detail: "업무 메신저 Bot으로 개인이나 채널에, 또는 사내 메일로 보냅니다. 메신저 인증 키는 게이트웨이에만 둡니다."
  - title: "기록 30일"
    detail: "완료 알림, 전송 시도, 감사 기록을 30일 보관합니다. 키 원문은 화면, DB, 로그 어디에도 남기지 않습니다."
{{< /flow >}}

운영 흐름은 세 단계로 단순하게 유지했습니다.

1. 웹에서 서비스를 등록합니다.
2. 등록 직후 한 번만 보여 주는 서비스 토큰으로 API를 호출합니다.
3. 현황 화면에서 접수, 재시도, 완료, 실패를 확인합니다.

| 항목 | 내용 |
|---|---|
| 받는 대상 | 사내 이메일, 메신저 사용자, 메신저 채널 |
| 메시지 | 텍스트, 최대 2,000자 |
| 중복 방지 | `Idempotency-Key` 헤더로 같은 요청은 한 번만 접수 |
| 전달 | 단일 Worker, at-least-once, 1분·5분·15분 재시도 |
| 한도 | 서비스 합산 하루 한도와 담당자 테스트 한도 |
| 보존 | 완료 알림, 전송 시도, 감사 기록 30일 |
| 권한 | 담당자는 자기 서비스만, 플랫폼 관리자는 전체 관리 |

- 메신저 API 인증 키는 게이트웨이에만 두고 화면, DB, 로그에 원문을 남기지 않습니다.
- 오류 진단을 위해 상대 API의 오류 응답은 시도별로 크기를 제한해 저장하고, 관리자 화면에서만 볼 수 있게 했습니다.
- 서비스마다 키를 따로 발급하지 않아도 되고, 키를 바꿀 때는 게이트웨이 한 곳만 수정하면 됩니다.

## 운영 데이터 조회 MCP 서버 (2026.07)

랙, 서버, 자산, 장애·변경 티켓을 찾으려면 여러 사내 시스템을 따로 조회해야 했습니다. LLM에게 바로 API를 맡기면 잘못된 인자로 조회하거나 필요 이상으로 조회할 위험이 있었습니다.

title: "MCP 서버 조회 흐름 · 단계를 눌러 보세요"
steps:
  - title: "자연어 질문"
    detail: "랙, 서버, 자산, 티켓 정보를 자연어로 묻습니다."
  - title: "사내 LLM 해석"
    detail: "LLM은 질문을 해석해 어떤 도구를 어떤 인자로 쓸지만 정합니다."
  - title: "MCP 서버"
    sub: "정해진 규칙으로 실행"
    tone: "ok"
    detail: "실제 실행은 정해진 규칙으로 합니다. 자산 조회는 한 번에 최대 3건이고, 이 제한은 LLM이 바꿀 수 없게 코드에 고정했습니다."
  - title: "읽기 전용 도구 11개"
    sub: "CI · 티켓 · 재고 · 도달성"
    detail: "랙·서버·네트워크·스토리지 CI, 장애·변경·작업 티켓, HDD·메모리·NIC 재고 조회 10개와 자산 도달성 확인 1개입니다. TTL 캐시를 씁니다."
  - title: "응답"
    detail: "출처, 캐시 여부, 조회 조건, 경고를 같은 형식으로 담아 돌려줍니다."
{{< /flow >}}

- 사내 운영 API를 읽기 전용 MCP 도구 11개로 정리했습니다(조회 10개, 도달성 확인 1개).
- 자연어 질문은 사내 LLM이 먼저 해석하고, 실제 도구 실행은 정해진 규칙대로 처리합니다.
- 도구 설명, LLM 계획 프롬프트, 실행 시 검증이 같은 파라미터 규칙을 쓰도록 맞췄습니다.
- 자산 조회는 한 번에 최대 3건으로 묶고, 이 제한은 LLM이 바꿀 수 없게 코드에 고정했습니다.
- 응답에는 출처, 캐시 여부, 조회 조건, 경고를 같은 형식으로 담았습니다.
