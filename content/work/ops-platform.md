## 알림 발신 게이트웨이 (2025.11 – 현재)

- 서비스마다 메신저 Bot 키와 메일 설정을 따로 들고 있어 키 관리와 감사가 흩어져 있었다.
- 사내 서비스가 **서비스 토큰 하나**로 업무 메신저 Bot · 메일을 보내는 발신 전용 게이트웨이를 만들었다.
- 서비스별 토큰과 감사 로그로 누가 무엇을 보냈는지 추적한다.
- 판단: **키는 게이트웨이 한곳이 쥐고, 앱은 게이트웨이를 거친다.** 키를 바꿀 때도 한곳만 바꾸면 된다.

## 운영 데이터 조회 MCP 서버 (2026.07)

- 랙 · 서버 · 자산 정보를 찾으려면 여러 사내 시스템을 오가야 했다.
- 사내 운영 API 를 **읽기 전용** MCP 도구 10개로 정리하고, 자연어 질문은 사내 LLM 이 해석한 뒤 실제 실행은 정해진 규칙으로 처리
- 자산 조회는 한 번에 최대 3건으로 묶는 정책을 코드로 고정해 LLM 인자로 바꿀 수 없게 함
- 판단: **LLM 은 해석만, 실행은 결정적으로.** 운영 데이터에서는 같은 질문에 같은 조회가 나가는 것이 중요하다.

## 배포 서버 보안 · 자원 감시 (2026.10)

- 호스트와 실행 중인 컨테이너의 설치 패키지를 모아 CVE 데이터와 대조하는 대시보드
- 사내 지원 base image 목록을 표로 관리해 교체 대상 판단
- 1분 cron 자원 기록과 메일 알림 ([관련 글](/posts/cron-resource-log/))
