Project Background

The project started after anthracnose damage on my father's grape farm in 2025. The goal is to reduce preventable crop loss by combining weather-aware risk estimation, grounded disease guidance, and an interface that remains understandable for elderly farmers.

This is not positioned as an LLM-first demo. It is planned as a production-minded platform that emphasizes trust, traceability, and operational discipline from the start.

Reliability Principles

Rule engine first

Disease risk scoring is planned around explicit rules plus Random Forest support so the prediction layer remains auditable and trustworthy.

LLM as an explanation layer

The language model is limited to explanation, checklist generation, and simplification for elderly users. It is not the disease decision engine.

Official-source grounded RAG

Responses are planned to be grounded in official agricultural guidance from trusted sources such as RDA and NCPMS to minimize hallucination risk.

AWS-native architecture

Platform

  • AWS EKS in Seoul region
  • Terraform + Helm for reproducible setup
  • ArgoCD for GitOps-driven delivery

Inference and application

  • FastAPI backend for API orchestration
  • KServe + vLLM for model serving
  • Redis, PostgreSQL, and ChromaDB for runtime support

Operations

  • Prometheus, Grafana, and Loki for observability
  • Karpenter + HPA for autoscaling
  • Spot-first strategy for cost optimization

Roadmap and KPI Targets

Roadmap

  1. Phase 0: API access and EKS baseline setup
  2. Phase 1: FastAPI core service and rule engine
  3. Phase 2: KServe, vLLM, and RAG integration
  4. Phase 3: Observability and autoscaling layer
  5. Phase 4: GitOps, CI/CD, and hardening
  6. Phase 5: README, demo, and portfolio packaging

KPI Targets

  • Anthracnose risk prediction accuracy: 90%+
  • Average LLM inference latency: under 2 seconds
  • GPU monthly cost reduction: 40%+ vs on-demand
  • Grounded response rate after RAG: 95%+

Why AWS Activate

AWS credits would directly support EKS validation, GPU-backed inference experiments, observability setup, and autoscaling tests in a realistic environment. The objective is to validate a production-oriented architecture early, not to build a superficial demo.

The project is intended to prove that agricultural AI can be both trustworthy and operationally practical when prediction logic, grounded retrieval, and cloud-native operations are designed together.
